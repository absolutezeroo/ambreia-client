## Les quatre coutures

1. **DI.** `ComponentContext.attachInstance(iid, instance)` enregistre un objet simple ; toute demande
   (avant ou après) reçoit l'objet. `AvatarRenderManager` et `AssetLibrary` sont des classes simples ;
   le moteur construit le premier quand la configuration est complète, avec `IAvatarRenderOptions`
   (bibliothèque d'assets, quatre URL, rappel de chargement).
2. **`Core.instance`** : remplacé par l'option `onLibraryLoaded` (barre de chargement).
3. **`room/`** : les types graphiques sont descendus dans `common` ; `avatar` n'importe que `common`
   (mur ESLint testé, `tsc` autonome).
4. **Navigateur** : le chemin de rendu passe par la plateforme ; `textureFromCanvas()` garde
   `Texture.from()` dans le navigateur et une `ImageSource` sous Node (une `TextureSource` nue a une
   méthode d'envoi « unknown » et ne dessinerait rien sur GPU — vérifié). `fetch` reste natif.

## Preuve (§9, §11)

```
AMBREIA_ASSETS=http://vortex-assets.local node node_modules/tsx/dist/cli.mjs \
  --tsconfig packages/ambreia-avatar/tsconfig.json packages/ambreia-avatar/tools/render-avatar.mjs \
  hd-180-2.hr-828-31.ch-255-1408.lg-280-110.sh-305-62 out.png --direction 2 --zoom 2
```

Le script n'importe que `@ambreia/avatar`, `@ambreia/common`, `@napi-rs/canvas`, `linkedom` : ni
contexte DI, ni navigateur simulé, ni moteur. `packages/ambreia-avatar/test/render.test.mjs` compare
son PNG à `test/fixtures/reference-hd-180-2.png` (PASS ; sauté sans `AMBREIA_ASSETS`).

## Défaut trouvé par la preuve : les parties rognées étaient étirées

Le premier rendu Node différait de l'imager sur 3 108 pixels, avec des cheveux flous. Cause : un
`.nitro` rogne les marges transparentes (`frame` + `trim`) ; la vraie PixiJS donne à la texture sa
taille d'origine, et `AvatarImageCache` étirait le `frame` sur cette boîte. Le client du navigateur
avait ce flou depuis toujours ; le shim pixi de l'imager le masquait en renvoyant la taille du `frame`
(au prix d'ignorer le décalage de rognage, défaut qu'il documente lui-même pour le mobilier). Corrigé :
le `frame` est dessiné à son décalage de rognage et à sa taille, comme un sprite pixi — juste par
construction, puisque les offsets d'un asset Nitro se mesurent contre la boîte non rognée. La
référence du test est donc le rendu Node corrigé ; le rendu de l'imager reste l'ancien (son shim ne
porte pas de rognage pour les avatars) et décale encore les parties rognées d'un ou deux pixels.
