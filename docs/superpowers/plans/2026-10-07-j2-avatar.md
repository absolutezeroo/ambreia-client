# J2 — `@ambreia/avatar` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal :** sortir le rendu d'avatar du moteur en un paquet autonome `@ambreia/avatar`, qu'un script
Node utilise pour produire un PNG sans DI, sans navigateur simulé et sans le moteur.

**Architecture :** le rendu (`habbo/avatar` sans l'éditeur) devient un paquet qui n'importe que
`@ambreia/common`. Quatre coutures sont coupées, de bas en haut : les types graphiques de `room/`
descendent dans `common` ; les globaux du navigateur passent par une **plateforme** de `common`
(canvas, décodage d'image, XML, octets) que Node remplace ; `AssetLibrary` et `AvatarRenderManager`
deviennent des classes simples, que le moteur enregistre dans le DI par un `attachInstance()` ;
`Core.instance` devient une option. Puis `move-modules` déplace le rendu. L'éditeur reste dans le moteur
(futur `game`).

**Tech Stack :** TypeScript 5, PixiJS v8 (sa `Texture` se construit sous Node, vérifié), esbuild,
`@napi-rs/canvas` + `linkedom` (déjà dépendances de l'imager), `node:test` + `tsx`.

**Spec :** `docs/superpowers/specs/2026-10-07-client-architecture-design.md` (§3 règles 1–2, §8 studio
d'avatar, §9 J2, §11 test propre de J2).

## Global Constraints

- « À la fin de chaque jalon, le client compile, démarre et on entre dans une room. » (§9)
- « Les moteurs n'utilisent pas le DI : classes à constructeur simple, dépendances passées en
  paramètre (fournisseur d'assets, options typées, résolveur de textes, fabriques de canvas et de
  parser XML). `game` les enveloppe en composants. » (§3 règle 1)
- « `iso` PEUT dépendre d'`avatar`. L'inverse est interdit. » (§3 règle 2) — donc `avatar`
  n'importe pas `room/`.
- J2 : « Éditeur sorti vers `game` ; constructeur simple, options typées ; fabriques canvas et XML
  injectées ; `Core.instance` retiré ; imports `@vortex/common` ciblés (pas tous les chargeurs) ».
  Preuve : « Un script Node génère un PNG d'avatar en n'important que `@vortex/avatar` (+ `common`) ;
  l'imager n'a plus de shim pour les avatars ». (§9 — portée `@ambreia/` depuis le renommage Ambreia)
- J2 test propre : « Rendu d'avatar dans Node, comparé à une image de référence ». (§11)
- Nouveaux paquets : portée `@ambreia/<nom>`, dossier `packages/ambreia-<nom>` ; le plugin de dev les
  trouve seul.
- Commit par chemins explicites ; `pnpm check` vert avant chaque commit ; déplacements par
  `move-modules.mjs` (simulation sans violation avant `--apply`).

## Décisions prises par ce plan

| # | Décision | Pourquoi |
|---|---|---|
| D1 | `ComponentContext.attachInstance(iid, instance)` : le DI enregistre un objet simple | `IAvatarRenderManager` (21 membres, dont `get events()`) et `IAssetLibrary` sont trop larges pour une enveloppe par délégation ; l'enveloppe DI de §3 se réduit à une ligne jusqu'au kernel (J5). |

| D3 | La `Texture` de pixi reste ; un helper `textureFromCanvas()` remplace `Texture.from(canvas)` | `new Texture({source: new TextureSource({resource})})` marche sous Node (vérifié) ; `Texture.from` détecte le type de ressource par des globaux du navigateur. |
| D4 | `IGraphicAsset`, `IGraphicAssetCollection`, `GraphicAsset`, `GraphicAssetPalette`, `GraphicAssetCollection`, `RoomObjectSpriteData` descendent dans `@ambreia/common/graphics` | Ce sont des conteneurs d'assets génériques, sans dépendance à `room/` ; `room` pourra les importer de `common`, ce que la règle 2 permet. |
| D5 | `pets/` et `enum/AvatarGuideStatus` restent dans le moteur | Le rendu ne les importe pas ; seuls `room` et la fenêtre s'en servent. |

## Review Focus

1. **Une ressource chargée deux fois ou par la mauvaise plateforme** (plateforme changée après le
   démarrage, ou un site oublié qui lit encore un global) → sous Node, un global manquant lève
   `ReferenceError`. Pin : Task 7, le script Node tourne **sans** `installGlobals()`.
2. **Un consommateur DI reçoit l'enveloppe au lieu de l'objet** (`attachInstance` annonce le mauvais
   objet aux demandes en attente) → `RoomEngine`, `RoomUI`, le gestionnaire de fenêtres et l'éditeur
   reçoivent le vrai `AvatarRenderManager`. Pin : Task 1, test « a request queued before the attach
   gets the instance ».
3. **L'avatar est prêt avant la config** : `AvatarRenderManager` attendait l'événement `complete` de la
   configuration ; construit trop tôt, il lit des URL vides et n'affiche rien. Pin : Task 5, l'option
   est construite dans le gestionnaire de `complete`, vérifiée en direct (Task 8).
4. **Rendu différent après l'extraction** (ordre des calques, décalages, retournement) → pixels
   identiques à la référence prise avant. Pin : Task 0 (référence) + Task 7 (comparaison).
5. **La barre de chargement ne progresse plus** (`Core.instance.updateLoadingProcess` remplacé par une
   option non branchée). Pin : Task 5, le moteur passe `onLibraryLoaded` ; Task 8 regarde le chargement.

// packages/ambreia-common/src/platform/Platform.ts
/** What the engine packages ask of their host: the browser by default, Node in tools (spec §3 rule 1). */
export interface ICanvas2D
{
    width: number;
    height: number;
    getContext(type: '2d'): CanvasRenderingContext2D | OffscreenCanvasRenderingContext2D | null;
}

export interface IPlatform
{
    createCanvas(width: number, height: number): ICanvas2D;
    decodeImage(bytes: Uint8Array, mimeType: string): Promise<CanvasImageSource>;
    parseXml(text: string): Document;
    fetchBytes(url: string): Promise<ArrayBuffer>;
    fetchText(url: string): Promise<string>;
}

export const BROWSER_PLATFORM: IPlatform = {
    createCanvas: (width, height) => typeof OffscreenCanvas !== 'undefined'
        ? new OffscreenCanvas(width, height)
        : Object.assign(document.createElement('canvas'), {width, height}),
    decodeImage: (bytes, mimeType) => createImageBitmap(new Blob([bytes], {type: mimeType})),
    parseXml: text => new DOMParser().parseFromString(text, 'text/xml'),
    fetchBytes: async url => (await fetch(url)).arrayBuffer(),
    fetchText: async url => (await fetch(url)).text()
};

let current: IPlatform = BROWSER_PLATFORM;

/** The platform every engine package reads. Set it once, before the first load (a tool's first line). */
export function platform(): IPlatform
{
    return current;
}

export function setPlatform(value: IPlatform): void
{
    current = value;
}
```

import {Texture, TextureSource} from 'pixi.js';
import type {ICanvas2D} from '../platform/Platform';

/** `Texture.from(canvas)` guesses the resource type from browser globals; this does not, so it runs in Node. */
export function textureFromCanvas(canvas: ICanvas2D): Texture
{
    return new Texture({source: new TextureSource({resource: canvas, width: canvas.width, height: canvas.height})});
}

// packages/ambreia-avatar/tools/node-platform.mjs
// The Node side of @ambreia/common's platform: what the browser gives the engine, from
// @napi-rs/canvas and linkedom. A tool sets it once, before the first load.
import { readFile } from 'node:fs/promises';
import { createCanvas, loadImage } from '@napi-rs/canvas';
import { DOMParser } from 'linkedom';

export function nodePlatform({ assetsRoot = null } = {})
{
    const read = async url =>
    {
        if(assetsRoot && !/^https?:/.test(url)) return readFile(new URL(url, assetsRoot));
        const response = await fetch(url);
        if(!response.ok) throw new Error(`${response.status} ${url}`);
        return Buffer.from(await response.arrayBuffer());
    };

    return {
        createCanvas: (width, height) => createCanvas(Math.max(1, width), Math.max(1, height)),
        decodeImage: bytes => loadImage(Buffer.from(bytes)),
        parseXml: text => new DOMParser().parseFromString(text, 'text/xml'),
        fetchBytes: async url => { const b = await read(url); return b.buffer.slice(b.byteOffset, b.byteOffset + b.byteLength); },
        fetchText: async url => (await read(url)).toString('utf8')
    };
}
```
