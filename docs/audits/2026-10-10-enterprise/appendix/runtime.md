## E. Not verified, and why

- Anything past the login screen: room entry, HUD (`__ambreia.hud.demo()` has no view without a room), avatars in-room, furniture, chat, the 60-message wire contract — **no game server** (`../vortex-rpg-emulator` absent, `/webapi` → :8080 refused, no SSO ticket).
- Game WebSocket failure UX and reconnect behaviour — the client does not dial before login, so the socket path was never reached.
- Avatar PNG determinism, 20-avatar cache timing, `render.test.mjs` goldens — **no asset server** (`vortex-assets.local` unresolvable; clothing `.ambreia` directories are not in the repo); the tool exits 2 without `public/config.json` and times out (122 s) with an unreachable host.
- iso sandbox rendering (`zone.json`, `zone-stairs.json`, `?zone=big`), frame time at 100/500 objects, heap over 20 enter/leave cycles — the sandbox needs `furnidata_json` + the `room` (and `furniture`, `clothing`) directories from the asset server; without them `window.sandbox` never exists. The script to measure (`SP/iso.mjs`) is ready and uses `stage.getRoom('zone').createRoomObject`, `stage.loadRoom`, `sandbox.addAvatar`.
- Imager render endpoints (`/habbo-imaging/avatarimage`, `/furniture`) and behaviour without MySQL beyond its startup log — the process never listens without the asset host.
- Glaze editing round-trip (save to `vortex-layouts/`) — would write tracked files; only load/render was checked.
- Map editor beyond its login dialog — needs the emulator's `/api`.
- Absolute frame-time/fps numbers — headless Chromium on SwiftShader (software GL); only relative comparisons within this report are meaningful. `performance.memory` numbers are from `--enable-precise-memory-info`.
- Production build (`pnpm build`) — needs a release revision from the absent emulator; not attempted.
- `Vortex.instance` internals — only the global's existence was checked.
